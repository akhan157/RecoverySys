# Benchmark and validation reporting

Run `npm run -s report:benchmarks` from the app directory to produce a JSON report on stdout (requires Python 3). The report runs the current JavaScript model against the checked-in corpus, and compares four model outputs with the separately calculated analytic reference. Each row retains units, the signed difference, relative difference where the reference is nonzero, and review status. Corpus results include their recorded tolerances and whether they gate agreement. Domain coverage reports accepted and unreviewed cases.

These are comparison metrics, not a claim of model accuracy in flight. Shared equations, assumed inputs, rounding and selected examples limit the analytic comparisons. The existing corpus contains no independently accepted comparisons or real-flight cases. A passing regression tolerance is not an uncertainty estimate, and an average across unrelated outputs would be misleading. In particular, rounded landing energy can conceal differences.

To strengthen validation, follow `corpus/README.md`: document independent sources or flight observations, inputs, units, uncertainty and permissions; obtain a separate review and record it before accepting a case. Cover intended flight conditions and failure modes, and report measurement error and uncertainty per output and operating range. Investigate discrepancies before changing equations or tolerances; preserve regression cases and distinguish numerical changes from experimental evidence. Never manufacture a flight-accuracy percentage from these review cases.
